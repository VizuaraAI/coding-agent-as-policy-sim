Coding agent as policy

Language to motor commands, via Claude Code

Type a task. Click Send. A Claude Code agent (running in a sister terminal) reads the active camera and writes motor commands back through the HTTP API.
How this works (read me first)
  1. Forget calibration. Clears every skill file so the agent starts from nothing. Watch the working directory below empty out.
  2. Calibrate. Pick the Calibrate stage and Send. The agent runs trial motor commands, learns the vx, vy, omega mapping and how to avoid obstacles for each camera, and writes one skill file per camera.
  3. Open a skill file. The files appear in the working directory below. Click one to read what the agent learned.
  4. Execute. Switch to the Execute stage and Send. The agent drives to the green goal, avoiding obstacles.
  5. Move things. Randomize the goal, car, or obstacles. The agent keeps driving to the goal on its own, no new instruction needed.

The agent only sees the HTTP API, never the simulator source. Reset just repositions the car; Forget calibration deletes the learned skill files.

          What the agent can access (HTTP API only)
          
    
            The agent gets only these HTTP endpoints. It cannot read or change the
            simulator source, so it cannot move the car directly through JavaScript. It must learn the
            car by experiment, exactly like a real robot.
          
    
          
    GET  /api/instruction        → { instruction, stage, activeCamera, ... }
GET  /api/camera             → PNG (active camera view)
GET  /api/camera?view=front  → PNG (a specific camera)
POST /api/camera  { camera } → switch the active camera
GET  /api/state              → { pose, goal, obstacles, ... }
POST /api/motor   { vx, vy, omega, duration }
POST /api/log     { message }
GET  /api/calibration?camera=top_down → saved mapping or null
POST /api/calibration { camera, calibration }   → write a skill file
